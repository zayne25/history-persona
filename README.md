# 你在历史中的名字

历史人物性格匹配测试 · 网页版（M1 可玩版本）

> 24 个没有标准答案的抉择，把你的选择折算成一组六维坐标，再从 36 位历史人物里找出与你距离最近的那一个。

零依赖、零构建：直接打开 `index.html` 即可运行；也可通过任意静态服务器托管。

```powershell

# 方式二：本地静态服务器（推荐，便于调试分享链接）
```

## 一、性格模型：六维连续谱

不用 MBTI 式分类。理由：粒度太粗、边界生硬、且增加人物需要重新定义类别。改用连续坐标后，人物是空间中的一个点，匹配结果天然可以给出「匹配度 %」并持续扩展。

| 编号 | 维度 | 负极 (0) | 正极 (100) | 权重 |
|---|---|---|---|---|
| D1 | 义利观 | 守义 | 图功 | 1.3 |
| D2 | 行动力 | 静水 | 雷霆 | 1.3 |
| D3 | 人际取向 | 独行 | 群策 | 1.0 |
| D4 | 思维方式 | 建制 | 权变 | 1.0 |
| D5 | 情感驱动 | 冷澈 | 深情 | 0.9 |
| D6 | 表达形态 | 立功 | 立言 | 0.9 |

D1–D2 决定人格辨识度，D3–D4 决定行为模式，D5–D6 决定气质与结局感。

## 二、题型设计

| 题型 | 题数 | 作用 |
|---|---|---|
| sjt 情境判断 | 13 | 主力计分，每题刻画 2–3 个维度 |
| rank 优先级排序 | 4 | 拉开强度差，信息量远大于单选 |
| slider 价值滑杆 | 4 | 直接校准某一维度的强度 |
| flip 反向自检 | 4（2 组） | 前后一致性检测，生成可信度标签 |
| fun 趣味轻量 | 2 | 不计入坐标，生成结果关键词 |

题库按幕次编排：**破冰 6 题 → 核心 12 题 → 收束 9 题**，每幕切换时给出转场文案，缓解作答疲劳。

> **关于决胜题**：方案最初设计了「平局时才追加的决胜题池」。实测证明这个设计有害——同一用户两次作答，一次触发加试、一次没触发，结果必然不同，重测信度因此被压到 63.7%。于是把那 3 道题**并入常规题库**（24 → 27 题），流程更简单、结论更稳定。

编写规范：不出现现代专有名词；**不要求任何史实知识**；四个选项在用户视角都说得通，禁止诱导性的「正确答案」。

## 三、匹配算法

```
1. 原始分    raw_d = Σ w_q · Δ(q, d)
2. 标准化    T_d = clamp((raw_d − lo_d)/(hi_d − lo_d) × 100, 0, 100)
               其中 lo/hi 用 config.calib —— 4000 份模拟作答的 p1/p99 实测分位数
3. 相似度    S_dist = 1 − √(Σ w_d Δ² / Σ w_d) / 100
             S_cos  = Σ w_d·(Tᵘ−50)(Tᵖ−50) / √(Σ w_d(Tᵘ−50)² · Σ w_d(Tᵖ−50)²)
             S      = 100 · (α·S_cos + (1−α)·S_dist)，α = 0.35
4. 平衡调优  S' = S − λ·(热度 − 0.5)，λ = 3
5. 排序      Top1（主结果）+ Top2/3（次级可能）+ 最远 1 人（历史对立面）
6. 兜底      最高分 < 55 → 触发「未被记载的人」
7. 口径      展示值做单调分段再标定，永不显示 100%
```

参数集中在 `assets/js/core/matching.js` 顶部的 `MATCH_CONFIG`，支持热更新与 A/B。

**为什么标准化不用理论极值**：遍历「所有可能作答」得到的极值远宽于真实作答范围（如 D5 理论跨度 189，真实作答只用到 135），min-max 之后坐标全挤在中段，结果是「谁都差不多像」、匹配度普遍虚高。改用实测分位数后，最弱维度区分度从 14.9 升到 22.5，最热人物占比从 18.8% 降到 11.2%。它仍是题库的固定属性（离线统计后写死），因此跨时间、跨设备的结果依旧可比。

**为什么余弦要先减 50**：六维坐标全为正，直接算余弦会让任意两人的值都趋近 1，等于「谁都相似」，实测把展示匹配度的中位数顶到 97%——这个数字也就失去了意义。减去中位后再算（本质是皮尔逊相关），衡量的才是轮廓起伏是否同形。若用户轮廓过于平坦（离散度 < 10），余弦不可靠，自动退化为距离口径。

**健康度判据**：见 `tools/analyze.js` 与 `analysis.html`。4000 份混合人群模拟（认真 35% / 一般 50% / 乱点 15%），当前 **9 / 10 项通过**：覆盖率 97.2%、最热人物 11.2%、最弱维度区分度 22.5、匹配度落在 70–95 区间的占 90.9%；唯一未达标的是重测信度 64.5%（目标 70%），原因与取舍写在报告页。

## 四、人物库

**选取范围**：中国史 24 人（上古—清），世界史 12 人（古希腊—近代）。

**准入**：时间止于近代以前（排除在世者及逝世不足七十年者）；史料充足且学界对其主要特质有较高共识；在某领域有明确、可讲述的代表性成就。

**排除**：主要历史评价围绕大规模屠杀、殖民掠夺或极端暴政者；宗教先知与在世宗教领袖；当代与近现代政治争议人物。

**均衡性约束**（已通过自动巡检）：女性 9/36 = 25%；领域分布：文学 12、政治 11、军事 8、科学 8、思想 6、艺术 6、社会事业 6、史学 2、探索 2；跨越 8 个时期。

**人物信息结构**（`figures-*.js`）

| 字段 | 说明 |
|---|---|
| `id` / `name` / `alias[]` | 稳定标识与别称 |
| `lifespan` / `era` / `region` | 生卒、朝代、地域 |
| `fields[]` | 领域标签：politics / military / thought / literature / art / science / exploration / social / history |
| `gender` / `sensitivity` | 均衡性巡检与合规复核用 |
| `glyph` / `motif` | 印章头像主字与装饰母题（用于程序化绘制） |
| `tagline` / `quote` + `quoteSource` | 一句话判词、代表句及出处 |
| `traits[]` | 性格关键词 |
| `vector` | 六维标定坐标 |
| `evidence{}` | **每个维度对应的史料依据条目**（可展开查看，内容护城河） |
| `summary` / `deep` | 80 字简介 / 深度解读 |
| `milestones[]` | 代表成就年表（含年份） |
| `whatIf[]` | 「如果你是 TA」三则情境推演 |
| `counterpart` | 历史对立面（人物 id） |
| `further[]` | 延伸阅读 / 影视纪录片 |
| `popularity` | 初始热度，用于稀有度加成 |

**标定方法**：双人独立标定 → 分差 > 15 的维度进入第三方仲裁；每个维度的坐标必须附至少一条史料依据；坐标调整需生成新的 `calib` 版本号并在更新日志说明（旧结果链接按版本路由，保证不失效）。

## 六、视觉风格与交互

**方向：古籍新译** —— 东方纸本质感 + 瑞士式网格排版。

| 角色 | 色值 |
|---|---|
| 宣纸底 | `#F3ECDC` |
| 墨黑 | `#1C1A17` |
| 朱砂红（唯一强调色） | `#C4442F` |
| 石青 | `#2E5668` |
| 鎏金 | `#C39A3B` |

- 字体：标题思源宋体（文化感）+ 正文黑体（可读性）；数字单独用高对比衬线体，配合滚动动画成为视觉锤。
- **强调色纪律**：朱砂红只用于「用户此刻最该注意的一件事」，滥用会立刻俗气。
- **人物画像：全部由代码现画**（`assets/js/core/portrait.js`），不使用任何外部图片。
  原因有三：保持零依赖与断网可用；36 张来源不一的图会破坏视觉统一；规避版权与史实失真。
  做法是白描半身像 —— **冠巾定身份、器物定事迹、服饰定时代、眉眼须发定气质**：
  6 种服饰（交领 / 圆领 / 甲胄 / 披袍 / 西式 / 僧袍）、8 种冠巾（巾 / 冠 / 冕 / 盔 / 簪 / 桂冠 / 宽檐帽）、
  23 种手持器物（孔子执简、诸葛亮羽扇、张衡浑天仪、李白举月、成吉思汗弯弓、郑和宝船、
  伽利略望远镜、居里夫人烧瓶、南丁格尔提灯、梵高向日葵、贞德旗帜……）。
  神态由六维坐标微调（行动力高则眉上扬、情感驱动高则眼作弧），因此同一套部件不会千人一面。
  视觉特征与史料内容分离存放于 `assets/js/data/portraits.js`，改形象不必动史料数据。

  调试工具：`node tools/preview-portrait.js kongzi` 输出 ASCII 轮廓，
  `node tools/preview-portrait.js --check` 逐人绘制并捕获异常（改画像后应跑一遍）。
- 动效：选项选中 200ms 墨点扩散；翻题 250ms；匹配度数字滚动 900ms（情绪峰值）；雷达图 700ms（先你后 TA，制造「重合度」观感）；翻牌 400ms；印章落印 350ms 轻微过冲。除数字滚动外一律 ≤300ms，并支持 `prefers-reduced-motion` 降级为瞬时。
- 无障碍：对比度达 WCGA AA；不以色相为唯一信息载体（雷达图用实线/虚线区分）；全站可键盘操作；雷达图提供等效数据表。
- 分享卡：竖版 3:4，含立绘、判词、匹配度与悬念文案；提供多套模板降低重复刷屏感。

## 七、数据存储与可扩展性

**架构：静态优先 + 轻量 Serverless（可选）**

| 层 | 选型 |
|---|---|
| 前端 | 静态站点（当前为纯 HTML/CSS/JS，无构建步骤） |
| 内容源 | 人物库与题库以 JS 数据文件存于仓库（content-as-code） |
| 计算位置 | **全部在浏览器端** |
| 可选后端 | Cloudflare Workers + KV：仅用于短链、计数与远程配置 |

**结果令牌**：六维坐标 + Top1 + 次级与对立面编码进 URL（Base64url），附加轻量哈希签名防手改。任何人在任何设备打开同一链接得到同一结果，无需服务端、无需重新答题。

**构建期体检**分两层：

- `tools/validate-data.js`（结构层）：题目维度完整性、人物 `vector` 长度与范围、id 唯一性、对立面引用有效、女性占比与政军占比阈值、各维度赋分覆盖次数。
- `tools/analyze.js`（行为层）：4000 份混合人群模拟，检查结果分布是否健康、维度是否真能区分人、乱答能否被识别、同一人格两次作答是否稳定。**增删题目或人物、调整算法参数后都应重跑一次**——本轮的五处算法缺陷就是它逼出来的。

**扩展方式**

| 需求 | 做法 |
|---|---|
| 新增人物 | 在包文件里追加一条数据即可，**零改代码** |
| 主题题库包 | 新建 `figures-xxx.js` 并放入 `FIGURE_PACKS`；各包可携带权重覆盖表 |
| 新增维度 | 升级 `schema_version`，旧链接按版本路由到旧逻辑，历史链接不失效 |
| 算法调参 | `MATCH_CONFIG` 全部可热更新，便于 A/B |
| 多语言 | 文案与题库 key 化，人物保留原名 + 罗马音字段 |
| 开放 API | 预留人物查询与向量检索接口 |

## 八、隐私与合规
